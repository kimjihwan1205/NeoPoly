# NeoPoly 1차 QA — 테마·반응형·사용성·기능 신뢰성

검사일: 2026-09-12

대상: 현재 로컬 작업본, `http://localhost:3000/`

방식: 실제 화면 점검 + 키보드/탐색 테스트 + 코드의 이벤트·저장 경로 확인 + 기존 자동 검사

## 결론

시각적인 방향과 주요 화면은 갖춰져 있지만, **사용자가 기대하는 행동의 결과가 실제로 남는지**를 우선 정리해야 합니다. 가장 큰 문제는 다크/라이트 모드 자체보다, 작동하는 UI와 시연용 UI가 같은 완성도로 노출되어 구분되지 않는다는 점입니다.

- 디자인: 라이트 모드의 금색 텍스트·상태색 대비, 일부 다크 배경 잔존을 우선 보완해야 합니다.
- 반응형: 1024px 헤더 겹침, 좁은 PC 창의 AI 스튜디오 가로 넘침, 작은 화면에서 사라지는 기능 진입점이 중요합니다.
- 사용자 경험: 탐색 조건 복원, 모달 포커스 관리, 수집 결과 확인이 부족합니다.
- 기능: 문의 전달·프로필 저장·검색 결과 이동·구매 파일 다운로드 등에서 구현이 끊겨 있습니다.
- 기획: MVP에서 실제로 작동할 기능과 시연만 할 기능을 먼저 구분해야 합니다.

이번에는 앱 코드를 수정하지 않았습니다. 실제 결제·문의 전송·사용자 자료 삭제·휴지통 비우기·배포도 실행하지 않았습니다.

## 범위와 판정 방식

### 이번에 본 범위

- 공통 헤더, 프로필 메뉴, 테마 전환, 검색, 푸터, 플로팅 패널 관련 코드.
- Discover, Market/Art 상세, 썸네일 갤러리, 제작자 문의 모달.
- 계정 설정, 고객지원, 찜한 작품, 구매한 에셋.
- 보드·AI 스튜디오·프로젝트·콘텐츠 관리는 기본 화면 및 핵심 이벤트/저장 경로를 확인했습니다. 전체 생성·편집·복구 시나리오는 2차 대상입니다.

### 실제 확인한 화면 크기

| 화면 크기 | 주요 점검 |
|---|---|
| 1440 × 900 | 다크/라이트 상세, 문의 모달, 계정 설정, 헤더 |
| 1280 × 500 | 높이가 낮은 PC 창의 계정 설정 |
| 1024 × 768 | 헤더 메뉴와 검색창 충돌 |
| 768 × 1024 | 태블릿 폭의 스튜디오·보드·콘텐츠 관리·계정 설정 |
| 390 × 844 | 주요 페이지의 좁은 폭, 상세 갤러리, 썸네일 선택 |
| 320 × 568 | 최소 폭 및 리플로우 |

내장 브라우저의 뷰포트 크기를 바꿔 확인했습니다. 입력 장치는 마우스 조건을 유지하므로 **실제 iOS/Android 터치 기기 시험과 같지 않습니다.** 특히 `pointer: fine` 조건의 문제는 ‘창을 줄인 PC’에서 재현된 문제로 구분합니다. 실제 사용자 참가자를 모집한 사용성 테스트도 아닙니다.

### 우선순위

- **P1 — 우선 수정:** 핵심 행동 실패, 잘못된 완료 안내, 데이터 불일치, 주요 기능 접근 불가.
- **P2 — 다음 수정:** 가독성, 일관성, 불필요한 조작, 접근성, 반응형 품질.
- **P3 — 완성도 향상:** 표현·구조 정리, 장기적인 운영 품질.

근거의 ‘화면’은 실제 재현, ‘코드’는 현재 구현 확인, ‘제안/추가 검증’은 버그로 단정하지 않은 개선 항목입니다. 시연용 구현은 반드시 버그라는 뜻은 아니지만, 실제 기능으로 오해하게 만들면 P1로 분류했습니다.

## 먼저 해결할 10가지

1. **Discover의 9~60번 카드가 상세로 이동하지 않는 문제**와 미등록 상세의 잘못된 대체 데이터.
2. **제작자 문의·고객지원 문의가 실제 저장/전달 없이 완료로 표시되는 문제.**
3. **메모·레퍼런스 수집 버튼이 저장 대신 보드 페이지로만 이동하는 문제.**
4. **프로필 변경사항 저장, 콘텐츠 검색/필터, 업로드 등 핵심 버튼의 미구현.**
5. **찜·수집·가격 변경 등 저장 범위가 기능마다 다른 문제.**
6. **1024px에서 Support 메뉴와 검색창이 겹치는 문제.**
7. **좁은 PC 창에서 AI 스튜디오가 최소 960px 폭을 유지하는 문제.**
8. **라이트 모드의 금색 가격/선택 상태와 밝은 상태색의 낮은 대비.**
9. **문의 모달에서 포커스가 배경으로 빠지고 헤더가 활성 상태로 남는 문제.**
10. **레퍼런스 ‘휴지통 비우기’가 영구 삭제가 아니라 복원처럼 동작하는 코드.**

개발 브라우저 로그에는 Vite 개발용 WebSocket 연결 경고가 있었습니다. 화면은 정상 렌더링되었고 이를 운영 서비스 장애로 판정하지 않았습니다.

## 8. 다음 QA 순서

### 2차 — 보드 / AI 정리 / 생성 / 콘텐츠 관리의 실제 작업 흐름

1. 노트 만들기 → 이미지 추가 → 저장 → 화면 이동 → 다시 열기.
2. 레퍼런스 수집 → 수동 그룹 → 그룹 해제 → 프로젝트 연결 → 연결 해제.
3. 삭제 → 휴지통 확인 → 복원 → 기존 그룹/관계 복구. 실제 삭제 검사는 사용자 자료 대신 승인된 테스트 자료로 진행.
4. AI 정리: 기존 그룹 제외/포함, 결과 미리보기, 일부 적용, 취소, 되돌리기, 재실행.
5. 이미지 생성 → 턴어라운드 → 모델링 → 프로젝트 저장 → 이어서 작업하기. 시뮬레이션과 실제 결과 저장을 분리 판정.
6. 콘텐츠 가격/상태 변경 → 목록 반영 → 재진입 유지 → 판매 상세 일치.

### 3차 — 실기기 / 배포 환경 / 운영 준비

- iOS Safari·Android Chrome의 터치 스와이프, 키보드 표시, 주소창 높이 변화, 가로 회전.
- Windows/Firefox/Safari 스크롤바와 드래그, 확대 200~400%, 모션 감소.
- 운영 사이트의 직접 URL 진입·공유 미리보기·API 응답·오류 복구·느린 네트워크.
- 계정/서버 저장/권한/개인정보/파일 다운로드 검증은 기능 연결 이후 별도 진행.
