## 결론

이번에는 화면별로 따로 수정하기보다, **저장한 데이터가 다른 화면에서도 같게 보이는지**, **클릭한 결과가 실제로 일어나는지**, **작은 화면에서도 핵심 기능에 접근할 수 있는지**를 묶어서 개선했습니다.

노트 편집·저장, 그룹 저장·되돌리기, 검색 결과 이동, 찜 목록 재진입, 콘텐츠 필터, 주요 모달의 키보드 조작 등은 로컬 MVP 범위에서 보완했습니다. 반면 실제 AI·인증·결제·문의 전달을 새로 구현한 것은 아닙니다. 이 기능들은 시연 또는 준비 중이라는 안내를 명확히 했습니다.

1차의 63개 점검 항목과 2차의 15개 추가 항목을 **모두 해결했다는 의미는 아닙니다.** 일부는 우선 위험만 줄였고, 관계 데이터 통합·운영 기능·전체 디자인 토큰 정리 등은 아래에 남은 과제로 구분했습니다.

이번 작업은 로컬에만 반영했습니다. Git 커밋·푸시와 Vercel 배포는 실행하지 않았습니다.

## 1. 디자인 / 다크·라이트 모드

### 수정한 내용

- 라이트 모드의 중요한 가격·수익 금액과 헤더 활성 메뉴는 읽기 쉬운 어두운 텍스트로 분리했습니다. 브랜드 금색 자체는 유지했습니다.
- 콘텐츠 관리의 성공·오류·경고 상태 텍스트를 라이트 배경에 맞게 조정했습니다.
- 모바일 콘텐츠 관리의 상단 탭 바에 남던 고정 다크 배경을 테마에 맞는 배경으로 바꿨습니다.
- 정리된 그룹 카드에 남아 있던 다크 그라데이션을 라이트 모드용으로 조정했습니다.
- 라이트 모드의 키보드 포커스 아웃라인을 장식용 금색과 분리했습니다.
- 다크 작업 화면에서 고정 회색으로 지나치게 흐리던 일부 보조 텍스트를 가독성 있는 텍스트 토큰으로 연결했습니다.

### 아직 남은 부분

- 모든 화면의 고정 회색·금색 텍스트를 의미별 토큰으로 완전히 전환한 것은 아닙니다.
- 페이지 제목, 프로젝트 상세 제목, 마케팅 제목의 역할별 크기 정리는 남아 있습니다.
- 고정 다크 클래스를 라이트 CSS가 덮어쓰는 구조가 여전히 많습니다. 새로운 화면에서 같은 문제가 반복되지 않도록 점진적인 공통 컴포넌트 전환이 필요합니다.
- 반투명 버튼이 여러 이미지 위에 놓이는 모든 조합의 대비를 검증한 것은 아닙니다.

요약: 중요한 정보의 가독성과 잘못 남아 있던 다크 배경을 우선 보완했습니다. 전체 디자인 시스템 정리는 후속 작업입니다.

## 2. 반응형 / 레이아웃

### 수정한 내용

- 1024px 헤더에서 내비게이션과 검색창이 겹치지 않도록 간격과 검색창 폭을 조정했습니다.
- 좁은 PC 창에서도 작업 화면이 강제로 960px 폭을 유지하던 규칙을 제거했습니다.
- 전역 최소 폭을 320px로 조정하고, 최소 폭에서 계정 설정의 문서 가로 넘침을 확인했습니다.
- 모바일 메뉴에 검색, 장바구니, 알림 진입점을 제공했습니다. 장바구니·알림 팝오버도 작은 화면 안에 배치되도록 조정했습니다.
- 모바일 보드의 노트·레퍼런스 필터를 통해 휴지통에 접근할 수 있게 했습니다.
- PC 상세 정보 패널은 현재 화면에 실제로 남아 있는 높이를 기준으로 내부 스크롤 영역을 계산하도록 수정했습니다.
- 새 페이지 이동 시 상단으로 이동하는 동작과 Discover로 돌아올 때 탐색 위치를 복원하는 동작을 구분했습니다.

### 상세 패널 측정 결과

1440 × 900에서 첫 진입 시 패널 상단은 약 569px입니다. 수정 후 높이는 약 307px, 하단은 876px로 화면 안에 들어옵니다. 본문을 내린 뒤 sticky 상태에서는 상단 92px, 높이 784px, 하단 876px로 유지됩니다.

패널 위에서 스크롤하면 패널 내부만 이동하고 문서는 그대로 유지됐습니다. 이미지 영역에서 스크롤하면 본문이 이동하는 것도 확인했습니다. 기존 독립 스크롤·자동 숨김 스크롤바 작업은 유지했습니다.

### 아직 남은 부분

- 태블릿 콘텐츠 관리의 통계 카드 밀도와 첫 작업물까지의 이동 거리는 추가 압축 여지가 있습니다.
- 실제 iOS/Android의 스와이프, Safari/Firefox, Windows의 항상 표시 스크롤바 환경은 별도 검증이 필요합니다.
- 갤러리·작업 캔버스의 의도된 가로 스크롤까지 없앤 것은 아닙니다.

요약: 강제 최소 폭, 헤더 충돌, 모바일 기능 누락, 상세 패널 높이 문제를 우선 해결했습니다. 실기기 시험은 남아 있습니다.

## 3. 탐색 / 접근성 / 인터랙션

### 수정한 내용

- Discover의 탭과 상세 필터 상태를 보존하도록 변경했습니다. ‘아트 → 와이번 상세 → 브라우저 뒤로가기’에서 아트 선택과 이전 탐색 위치가 유지되는 것을 확인했습니다.
- 헤더 로고·메뉴, 찜 버튼, 찜 목록 카드, 콘텐츠 관리 카드의 키보드 접근을 보완했습니다.
- 상세 썸네일은 구현되지 않은 탭 패턴 대신 선택 상태가 있는 이미지 버튼 그룹으로 정리했습니다.
- 제작자 문의, 고객지원 문의, AI 정리 옵션/결과, 수동 그룹, 빠른 수집, 보드 노트 상세 등 주요 모달에 공통 모달 레이어를 적용했습니다.
- 공통 모달은 배경 비활성화, 배경 스크롤 잠금, Tab/Shift+Tab 포커스 순환, Escape 닫기, 닫은 뒤 포커스 복귀를 처리합니다.
- AI Studio ‘이어서 작업하기’ 카드의 가로 드래그 처리가 일반 클릭까지 가로채던 문제를 수정했습니다. 실제 드래그가 시작된 뒤에만 포인터를 잡도록 변경했습니다.
- 프로젝트 공유·복사 버튼에 접근 가능한 이름을 추가했습니다. 복사는 실제 클립보드 쓰기가 성공한 뒤에만 완료를 안내하도록 변경했습니다.

### 아직 남은 부분

- 모든 기존 팝업을 공통 모달로 전환한 것은 아닙니다. 구매·프로젝트·일부 전체 화면 팝업과 모바일 메뉴의 포커스 처리는 추가 점검이 필요합니다.
- 헤더는 키보드 조작을 보완했지만 모든 항목이 실제 링크인 구조는 아닙니다. 새 탭 열기·링크 주소 복사까지 자연스럽게 지원하려면 링크 기반 내비게이션 정리가 필요합니다.
- 잘못된 상세 ID의 404/찾을 수 없음 화면, 전체 페이지의 탐색 상태 복원, 전체 입력 라벨 점검은 남아 있습니다.

요약: 마우스뿐 아니라 키보드로 핵심 흐름을 이용할 수 있게 보완했습니다. 전체 접근성 적합성 검증 완료를 의미하지는 않습니다.

## 4. 실제로 연결한 로컬 기능

### 노트 / 레퍼런스 / 그룹

- 노트 제목·본문·태그·이미지를 편집 상태에 연결하고, 초안과 명시적인 저장을 구분했습니다.
- 제목 필수 입력, 태그 중복 제거, 파일 형식·용량 제한, 이미지 입력 오류 처리를 추가했습니다.
- 사용자가 붙인 기존 이미지를 유지하며 저장합니다. 편집한 노트만 갱신하고 다른 노트를 덮어쓰지 않습니다.
- 목록, 보드 전체, AI 정리가 같은 저장 노트 데이터를 읽도록 맞췄습니다.
- AI 그룹, 수동 그룹, 레퍼런스 보드를 기기에 저장하여 재진입·새로고침 후에도 유지하도록 했습니다.
- 이미 묶인 항목 제외/포함 옵션을 실제 현재 그룹 상태와 연결하고, 병합 시 중복 소속·그룹 코드·연관 관계를 정리했습니다.
- 그룹 적용·해제 후 되돌리기를 제공했습니다. 되돌리기 이력은 현재 방문에서 최대 10단계이며 새로고침 후까지 보존되지는 않습니다.
- 즐겨찾기를 모두 해제했을 때 샘플 즐겨찾기가 되살아나지 않도록 수정했습니다.
- 휴지통 항목은 일반 목록·즐겨찾기·최근 보기에서 제외합니다.
- 복원 동작에 붙어 있던 ‘휴지통 비우기’ 문구를 ‘전체 복원/선택 복원’으로 바로잡았습니다. 영구 삭제 기능을 만든 것은 아닙니다.
- 직접 만든 레퍼런스 보드에서는 사용자가 고른 이미지 목록을 기준으로 표시하도록 했습니다.
- 레퍼런스 더 보기는 새 가짜 에셋을 만드는 대신 실제 목록의 다음 항목을 보여주도록 바꿨습니다.

### 수집 / 작품 탐색

- 이미지의 레퍼런스·메모 수집 버튼에서 저장 대상 선택 다이얼로그를 열도록 연결했습니다.
- 선택한 노트에 메모·이미지를 추가하거나 새 노트를 만들고, 레퍼런스는 선택한 보드의 구성 목록에 저장하도록 처리했습니다.
- 갤러리에서 현재 선택한 이미지를 수집 대상으로 넘깁니다. 수집 이력도 시작 시 지우지 않고 보존합니다.
- 9~60번 등록 작품도 각 작품의 제목·이미지로 상세를 열도록 변경했습니다. 상세 자료가 부족한 항목은 미리보기로 안내하고 구매를 비활성화했습니다.
- 작품 유형이 달랐던 MY POSCO 02의 목록 표시를 Art로 맞췄습니다.
- 함께 볼 작품 카드는 해당 작품의 등록 제목·유형·가격을 참조하도록 수정했습니다.
- 헤더 검색 결과 클릭과 Enter에서 해당 상세로 이동하도록 연결했습니다.
- 찜·팔로우를 기기에 저장하고, 상세와 찜 목록에서 같은 상태를 보도록 했습니다. 찜 목록 카드도 상세로 이동합니다.

### 프로젝트 / 계정 / 콘텐츠 관리

- AI Studio의 이어서 작업하기를 저장된 프로젝트 목록·고정 상태와 연결했습니다. 카드를 선택하면 해당 프로젝트가 열립니다.
- 프로젝트를 불러올 때 저장된 이름·설명·태그 등 변경 내용을 보존하도록 수정했습니다.
- 실제 수정일 추적 없이 항상 오늘로 보이던 ‘마지막 수정’은 ‘기록 없음’으로 표시했습니다. 수정 이력 기능은 아직 없습니다.
- 프로필 입력·이미지 미리보기·저장·취소를 연결하고, 헤더도 저장된 프로필 정보를 사용하도록 변경했습니다.
- 알림 설정 스위치는 기기에 저장되는 상태로 연결했습니다. 실제 메일·푸시 전송 설정은 아닙니다.
- 콘텐츠 관리의 검색·유형·상태·카테고리·정렬·페이지 이동을 실제 표시 목록에 연결했습니다.
- 결과 없음, 필터 변경 후 선택 초기화, 표시 목록 기준의 콘텐츠 개수, 가격 변경 저장을 보완했습니다.

요약: ‘클릭 → 결과 → 기기에 저장 → 다시 찾기’의 주요 경로를 연결했습니다. 계정 간 동기화나 서버 저장은 아닙니다.

## 5. MVP 안내로 구분한 기능

| 기능 | 이번에 바꾼 기대치 | 실제로 아직 제공하지 않는 것 |
|---|---|---|
| AI 보드 정리 | 내용·태그 규칙 기반의 제안이며 사용자가 확인 후 적용 | 실제 이미지 인식·외부 AI 모델 분석 |
| AI Studio 생성 | 샘플 기반 MVP임을 안내 | 실제 유료 AI 생성 요청·사용량 관리 |
| 이미지 유사도 검색 | 샘플 결과임을 표시하고 가짜 정밀도 완화 | 업로드 이미지의 실제 유사도 검색 |
| 제작자·고객지원 문의 | 필수 입력 확인과 로컬 초안/미전송 안내 | 상대방에게 문의 전달·답변·알림 |
| 보안 설정 | 비밀번호 입력·인증 설정을 비활성화하고 준비 중 안내 | 실제 비밀번호 변경·2단계 인증 |
| 언어 설정 | 현재 지원하는 한국어만 표시 | 영문·일문 전체 번역 |
| 구매 파일 다운로드 | 미지원 상태를 표시하고 비활성화 | 구매 권한 검증·실제 파일 제공 |
| 업로드·판매자 관련 미지원 버튼 | 준비 상태 또는 안내 화면으로 연결 | 실제 콘텐츠 심사·발행·정산 |
| 프로젝트 공유 | 이 기기에만 저장되며 공유 준비 중이라고 안내 | 다른 사용자에게 열리는 프로젝트 공유 링크 |

요약: 실제로 전송·생성·변경되지 않았는데 완료됐다고 말하던 주요 흐름을 정리했습니다. 안내를 붙였다고 기능 구현이 완료된 것으로 분류하지 않았습니다.

## 6. 저장 안정성

- 공통 저장 계층을 추가하여 같은 탭의 다른 화면과 다른 탭의 저장 변경을 구독하도록 했습니다.
- 빈 배열은 ‘사용자가 모두 지운 상태’로 보존합니다. 손상된 JSON은 기본값으로 처리합니다.
- 주요 저장 동작에서 저장 용량 초과 등의 실패를 확인하고, 전역 저장 오류 안내를 표시합니다.
- 화면을 여는 것만으로 초기값이 기존 사용자 데이터를 덮어쓰지 않도록 구성했습니다.

남은 한계:

1. 로컬 저장소는 계정별 서버 데이터가 아니므로 다른 기기와 동기화되지 않습니다. 브라우저 데이터 삭제 시 사라질 수 있습니다.
2. 전체 기존 저장 코드를 모두 전환한 것은 아닙니다. 프로젝트의 일부 낙관적 완료 안내 등은 추가 정리가 필요합니다.
3. 여러 저장 항목을 함께 갱신하는 작업에는 원자적 트랜잭션이 없습니다. 일부 저장만 실패했을 때의 복구 설계가 필요합니다.
4. 현재 검증은 기본 JSON 형식 중심입니다. 저장 데이터의 버전별 마이그레이션과 세부 스키마 검증은 남아 있습니다.

요약: 조용한 유실과 화면 간 불일치를 줄이는 기반을 마련했습니다. 실서비스 수준의 데이터 보존을 보장하는 단계는 아닙니다.

## 7. 확인한 사용자 흐름과 근거

아래는 이번 통합 작업 중 브라우저에서 확인한 결과입니다. 코드에서 연결한 모든 분기를 전부 직접 눌러 본 것은 아닙니다.

| 시나리오 | 확인 결과 |
|---|---|
| 새 노트 작성 → 제목 검증 → 저장 → 목록 → 새로고침 | 제목·본문·태그·이미지가 유지됐고, 다음 새 노트는 빈 상태로 열림 |
| 실제 저장 노트를 AI 정리 대상으로 사용 | 검증용 노트를 포함한 실제 9개 노트를 기준으로 옵션·제안 표시 |
| 그룹 3개 적용 → 1개 해제 → 되돌리기 → 새로고침 | 3개 → 2개 → 3개로 바뀌고 새로고침 후에도 적용 상태 유지 |
| 모바일 노트 휴지통 → 복원 | 휴지통 필터에 접근 가능하고, 복원 후 일반 목록으로 돌아옴 |
| 콘텐츠 검색 ‘엘프’ + Art 필터 | 일치하는 1개 콘텐츠만 표시 |
| 존재하지 않는 콘텐츠 검색 | 0개 결과와 빈 상태 표시 |
| 모바일 검색 ‘현대식’ → 상세 | 9번 작품의 이름·자체 이미지로 이동, 미리보기 구매 버튼 비활성화 |
| 와이번 찜 → 새로고침 → 찜 목록 → Enter | 찜 유지, 목록에 표시, 키보드로 같은 상세 진입 |
| Discover 아트 → 와이번 → 브라우저 뒤로가기 | 아트 탭과 이전 스크롤 위치 복원 |
| 제작자 문의 모달의 Shift+Tab·Escape | 포커스가 배경으로 빠지지 않음, 닫은 뒤 배경 활성화 |
| 이어서 작업하기의 와이번 카드 클릭 | 드래그와 클릭이 구분되고 와이번 프로젝트가 열림 |
| PC 상세 패널 내부 스크롤 | 이미지 본문 위치는 유지한 채 패널 내부만 이동 |
| 프로젝트 공유 버튼 | 공유 완료 대신 기기 저장/공유 준비 중 안내 표시 |

빠른 수집의 모든 저장 대상 조합, 프로필 저장의 모든 필드 조합, 프로젝트 정보 복사의 권한 거부 분기 등은 코드 경로를 확인했지만 브라우저 전체 시나리오 검증은 남아 있습니다.

### 수정 후 대표 반응형 확인

| 뷰포트 | 테마 / 화면 | 결과 |
|---|---|---|
| 320 × 568 | 라이트 / 계정 설정 | 문서 가로 넘침 없음, 미지원 보안 입력 비활성화 |
| 390 × 844 | 라이트 / 콘텐츠 관리·모바일 메뉴 | 검색·필터 펼침, 결과 목록, 장바구니·알림 진입 확인 |
| 390px 폭 | 다크 / 노트·상세 | 휴지통·복원 및 상세 탐색 확인 |
| 768 × 1024 | 라이트 / AI Studio | 작업 셸 폭 768px, 강제 960px 폭 없음, 프로젝트 카드 클릭 확인 |
| 1024 × 768 | 다크·라이트 / 홈 | 내비게이션과 검색창이 겹치지 않음 |
| 1440 × 900 | 다크 / 상세·문의 모달 | 정보 패널 높이·독립 스크롤·포커스 순환 확인 |

1024px 헤더에서 메뉴의 오른쪽 끝은 약 541px, 검색창 시작은 666px, 검색창 폭은 180px로 측정했습니다.

내장 브라우저의 뷰포트를 바꾼 검사이며 실제 터치 하드웨어 시험이 아닙니다. 모든 페이지 × 모든 화면 크기 × 두 테마의 조합을 통과했다는 뜻도 아닙니다. 실제 사용자 참가자를 모집한 사용성 테스트는 수행하지 않았습니다.

## 8. 자동 검사 / 실행 상태

- 타입 검사: 통과. 현재 프로젝트의 `lint`는 TypeScript 검사입니다. 별도 ESLint 전체 규칙 검사는 아닙니다.
- 자동 검사: 18개 통과, 0개 실패.
- 신규 검사: 빈 저장 목록·손상된 JSON·저장 용량 오류, 노트 갱신·태그 중복 제거, 그룹 병합·관계 중복 제거, 스튜디오 포인터 캡처 회귀 방지.
- 일부 검사는 계산/소스 규칙 검사입니다. 자동 브라우저 E2E 18개라는 의미는 아닙니다.
- 프로덕션 빌드: 성공.
- 최종 주요 JS: 1,655.62kB, gzip 434.54kB. 500kB 초과 청크 경고는 남아 있습니다.
- CSS: 213.03kB, gzip 31.30kB.
- 변경 내용의 공백 오류 검사: 통과.

9월 15일 재개 시 로컬 서버가 종료되어 개발용 WebSocket 연결 실패 이력이 있었습니다. 서버를 다시 시작한 뒤 `connected` 로그, 홈 렌더링, 오류 오버레이 없음, 기본 뷰포트에서 문서 가로 넘침 없음을 확인했습니다. 재연결 이후 확인 구간에는 새로운 오류 로그가 없었습니다.

브라우저 검증과 React 검토 스킬의 기준을 적용해, 단순 렌더링뿐 아니라 저장 후 재진입·포커스·드래그와 클릭 충돌도 점검했습니다. 브라우저 CLI를 사용할 수 없어 내장 브라우저 제어로 검증했습니다.

요약: 타입·빌드·18개 자동 검사는 통과했습니다. 번들 최적화와 자동 E2E 확대는 후속 과제입니다.

## 10. 테스트 데이터 / 반영 범위

- 기존 사용자 노트·프로젝트를 영구 삭제하지 않았습니다.
- 검증용으로 만든 `QA 검증용 노트 · 저장 연결 테스트` 1개는 복원 시험 후 휴지통으로 이동했습니다. 앱의 휴지통에서 복원 가능합니다.
- 시험 중 적용한 노트 AI 그룹은 기존 미적용 상태로 돌렸고, 테스트한 와이번 찜도 기존 해제 상태로 돌렸습니다.
- 검사에 사용한 테마는 다크로, Discover 탭은 전체로 돌렸습니다. 임시 뷰포트 설정도 해제했습니다.
- 로컬 서버는 다시 실행했고 홈 화면을 열어 두었습니다.
- 이번 개선은 로컬에만 반영됐으며, 운영 Vercel 페이지는 변경하지 않았습니다.
